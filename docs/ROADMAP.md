## 🟨 지금: 마지막 시험 (10/14 ~ 11/4) — 이걸 먼저 본다
**왜**: 위치 → 재고 → 발주 → 신호 → 루틴으로 옮겨 오면서 **문제를 앱에 맞추고 있었다** ("쥐어짜기"). 아직 "이거 때문에 정말 힘들다"고 **스스로** 말한 사장님이 없다. 그래서 끝을 미리 정하고 짧게 한 번만 더 본다.

- **누구**: 루틴이 없거나 깨진 사장님 **5명** — 창업 1년 안 · 가게를 넘겨받음 · 오토 운영 · 2호점 · 사장님이 자주 자리를 비움
- **어떻게**: **앱은 보여 주지 않는다.** 문제만 묻는다 (과거 질문). 답은 아래 기록표에 그대로
  1. "요즘 가게 하면서 **제일 짜증나는 게** 뭐예요?" (먼저, 아무 힌트 없이)
  2. "사장님 안 계실 때 **뭐가 떨어졌는지** 어떻게 아세요? 최근에 떨어지거나 버린 적은요? 얼마어치였어요?"
  3. "그거 해결하려고 **지금 쓰는 시간이나 돈**이 있어요?"
- **미리 정한 기준 (결과 보고 바꾸지 않는다)**
  - 5명 중 **2명 이상**이 ① 스스로 재고·발주 문제를 말하고 ② 이미 시간·돈을 쓰고 있다 → **계속** (그 사람들 대상으로 좁혀서)
  - 아니면 → **이 아이디어는 접는다** = "줄여서 두기" (앱은 그대로 열어 둠, 개발 멈춤)
- **그동안 개발 멈춤.** 버그만 고친다
- **같이 하는 것: 배달 메모** — 배달하면서 "이건 진짜 매일 짜증난다" 싶은 걸 **하루 한 줄**. `docs/DELIVERY_NOTES.md` (Claude에게 "배달 메모: …"라고 하면 날짜와 함께 적어 줌)
- **11/4에** 시험 결과와 배달 메모를 나란히 놓고 다음을 정한다: 계속 / 줄여서 두기 / 배달 쪽 새 문제

## 한 주 쓰는 법 (주 10시간)

| 언제 | 시간 | 할 일 |
|---|---|---|
| 평일 2일 | 1시간씩 | 고치기 — 사장님이 말한 것, 데이터 문제만 |
| 평일 2일 | 1시간씩 | 연락 — 방문 약속, 2주 뒤 안부 카톡, 카톡 채널 |
| 평일 1일 | 1시간 | 기록표 정리, 다음 쉬는 날 준비(인쇄 등) |
| 평일 1일 | 0 | **비워 두기** — 배달이 길어진 날이나 피곤한 날 |
| 쉬는 날 | 3~4시간 | 오전에 매장 1곳 세팅 또는 재방문 2곳 → **오후는 쉬기** |

- 하루 2시간은 **여유분**이다. 매일 2시간을 기준으로 잡지 않는다.
- 배달 수입이 먼저다. 앱 일 때문에 배달 시간을 줄이지 않는다.
- 계획보다 늦어지면 기간을 늘리지, 쉬는 날 오후나 잠을 줄이지 않는다.

## 1. 살펴보기 + 첫 세팅 (11월)

### 왜 바꿨나 (10/13)
지금은 "될 거예요"만 있고 증명이 없다. 평소엔 **있으면 좋은 것(비타민)**이고 대안(포스트잇·엑셀·기억·물어보기)이 많다. 그래서 먼저 **아픔이 진짜 있는지, 어디서 날카로운지**를 확인한다.
- 아픔은 평소엔 흐릿하고 **무언가 움직이기 직전·직후에 날카로워진다**: 알바·직원이 바뀐 첫 주, 사장님이 자리를 비울 때(쉬는 날 전화), 인수인계(매장 양도·매니저 교체), 이사·매장 이전, 매장 여러 곳 운영, 물류 입고일·재고 실사
- 위치 찾기보다 **다른 아픔**이 나올 수도 있다 (예: 알바 교육 전체 → "사진으로 만드는 매장 매뉴얼"). 그러면 방향을 튼다 — 실패가 아니다
- **두 갈래 가설 (10/14)**: 재고 세기·센 기록·포스기 구상이 가리키는 건 결국 **"뭘 얼마나 시킬까"(발주 예측)**
  - 위치 찾기: 아픔이 흐릿하고 가끔 날카롭다 · 발주: **매주 돌아오고 돈과 바로 이어진다** (떨어지면 못 팔고, 많이 시키면 버리거나 돈이 묶임) → 돈 낼 이유가 더 분명할 수 있다
  - 발주 앱만으로는 이미 하는 곳이 많다(포스사·식자재 주문 앱). 우리 강점은 이어지는 것: **어디 있는지 아니까 → 빨리 세고 → 세니까 발주가 맞는다.** 재고에서 제일 귀찮은 건 예측이 아니라 **세기**. 지도 = 세기를 쉽게 만드는 입구, 발주 예측 = 열매
  - 조심: 근거는 아직 인터뷰 한 곳(프랑스 한식당). 업종마다 다를 수 있다 (식당·카페 = 발주, 철물·의류처럼 물건 많고 천천히 도는 곳 = 위치). **12월 판단 기준으로 정한다**

### 재고 세기·발주 목록 시험 (10/13~)
설정 > 매장 > **재고 세기**를 켜면: 선반 순서대로 − 수량 + 로 세고, 물건마다 **기준**(이만큼은 있어야 함)을 적으면 모자란 것이 **발주 목록**으로 모여 카톡·문자로 보낸다. 실시간 추적이 아니라 **주기적으로 세기**. 서버 없음 (한 사람이 한 폰으로).
- ⬜ 프랑스 친구에게 카톡으로 4가지: ① 한 번 세고 발주 정리하는 데 **몇 분**, 얼마나 자주? ② 지난 한 달 **떨어져서 곤란 / 너무 많이 시켜 버린** 적? ③ 직원도 파일을 같이 보나, 혼자인가? ④ 발주는 어떻게 넣나 (문자·카톡·전화·거래처 앱)?
- ⬜ 친구가 **2주 실제로 쓰는지** + 시간·발주 실수 전후 재기 (무료로 쓰는 대신 매주 피드백)
- ⬜ 한국 식당 2곳에도 **"발주 어떻게 하세요?"** (10팀 살펴보기 질문에 추가)
- 가설: **해외 한식당**은 한국 식자재를 수입해 주문~도착이 길어 떨어지면 더 아프다 → 따로 확인
- 다음 후보 (반응 보고): 직원과 같이 세기(서버), 점검표 인쇄에 수량 칸, 유통기한
- ✅ **센 기록 남기기** (10/14): [다 셌어요]마다 날짜·물건별 수량을 몰래 남김 (백업에도 들어감, 화면 변화 없음)
- ⬜ **발주량 예측** — 기록이 2~3번 쌓인 뒤: 지난번보다 줄어든 만큼 = 쓴 양 → 하루 평균 × 다음 발주까지 날짜 − 지금 수량 = "4개 더". 들어온 날(늘어난 구간)은 빼고 계산. 친구 기록으로 맞는지 먼저 확인
- ✅ 살펴보기 질문에 **"포스기 뭐 쓰세요?"·"정산서에 메뉴별 판매 수 나와요?"** 추가 (위 10팀 살펴보기)
- ⬜ 친구가 2~3주 센 기록으로 낸 예측 ↔ **친구가 실제로 시킨 양** 비교 (12월 판단 기준의 숫자)

### 측정 — 세팅한 곳은 전·후를 잰다 (증명할 숫자)
| 잴 것 | 어떻게 | 언제 |
|---|---|---|
| **찾기 시험** | 가장 최근에 온 직원에게 **같은 물건 3개**를 찾게 하고 시간 재기 | 세팅 전 → 2주 뒤 → 한 달 뒤 |
| **"물어봄" 체크표** | 창고 문에 종이 한 장, "어디 있어요?" 물을 때마다 바를 정(正) 한 획 | 세팅 전 1주 → 세팅 후 1주 |
| **신입 교육 시간** | "새 직원이 위치 다 익히는 데 며칠 걸려요?" | 세팅 전, 세팅 후 신입이 오면 다시 |
| **또 산 것 / 버린 것** | "최근 한 달에 있는데 또 산 거, 묵혀서 버린 거 있어요?" | 세팅 전 → 한 달 뒤 |

**새는 돈 계산식** (예시는 가정 — 영업할 땐 꼭 "예를 들면"): 찾는 시간 = 하루 찾는 횟수 × 한 번 걸리는 시간 × 시급(2026년 최저 10,320원) × 30일 → 하루 10번 × 2분이면 **월 약 10만 원**. 물을 때마다 두 사람이 멈추니 사실상 두 배. 여기에 신입 교육 시간 × 1년 새로 오는 사람 수, 또 산 것·버린 것을 더한다. 측정한 숫자를 넣으면 "이 매장은 한 달에 ○만 원 줄었다"는 **진짜 사례**가 된다 (영업·가격 근거·사업계획서 재료). 숫자가 작게 나오면 그 업종은 우리 고객이 아니라는 뜻 — 그것도 결과다.


**사장님께 하는 말**: "써 주세요"가 아니라 **"필요하시면 제가 만들어서 붙여 드릴게요. 아니면 전혀 상관없어요."**

### 세팅 절차 — 찍고 → 컬러로 뽑아 → 전달하는 날 지운다
처음 드리는 종이가 첫인상이라 **컬러로 깔끔하게** 드린다. 매장 사진은 **전달하는 날 바로 지운다** (가능하면 세팅 당일).

**먼저 범위 정하기** (물건이 많은 매장일수록 — 약국·큰 식당 등. 다 하려면 하루가 날아간다)
- **물건 이름 대신 "종류"로**: "타이레놀, 판피린…" ✗ → **"감기약 → 3번 선반"** ✓. 선반 앞에 가면 이름은 보이니까, 지도는 "어느 선반으로 가나"까지만. 수천 개가 아니라 **20~40개**만 말하면 끝
- **진열대 말고 창고부터**: 진열대는 눈에 보인다. 헤매는 곳은 **뒤쪽 창고의 박스 재고**(박스 단위라 개수도 적다)
- **사진에는 번호만, 이름은 아래 목록**: 물건이 많으면 사진 지도보다 **큰 글씨 목록·전체 찾아보기** 양식
- **무료는 시간으로 끊기**: "무료는 **창고 한 면, 30분**까지". 나머지는 직원이 물건 넣을 때마다 앱에 하나씩 적거나, 나중에 유료 세팅

**방문 1 — 찍고 적기 (30~40분, 한가한 시간에)** · 챙길 것: 내 폰(충전), 폰 데이터(AI 구역 찾기용)
1. **시작 전**: 내 폰 앱이 **비어 있는지** 확인. 내 폰은 설정 > 사용 통계 보내기 **꺼짐**
2. **사진**: 선반·랙을 한 면씩 가까이서 정면으로. 사람 얼굴·택배 송장·서류는 안 나오게
3. **구역**: [AI로 구역 찾기]로 빠르게 나누고 손으로 다듬기
4. **물건**: 사장님·직원과 같이 돌면서 **음성 입력**으로 받아 적기 ("여기는 빨대, 냅킨, 컵홀더") — 무엇이 어디 있는지는 매장 사람만 안다
5. 설정에 **매장 이름** 넣기 (인쇄물 머리글에 들어감)

**인쇄 — 가능하면 그날 바로**
6. 집 컬러 프린터 또는 **근처 편의점 컬러 출력**(PDF 받기 → 출력) — 선반 옆엔 사진 지도, 입구엔 전체 찾아보기
7. 끝을 가위로 다듬어 **PP 클리어파일**(또는 철제 선반이면 **자석 클리어 포켓**)에 넣기

**방문 2 — 전달하고 지우기 (10분, 그날 다시 들르거나 커피 마시러 갈 때)** · 챙길 것: 인쇄물, 떼어낼 수 있는 양면테이프·마스킹테이프
8. **붙이기**: 선반 옆·창고 입구에 붙여 드리기
9. **백업 파일 넘기기** (설정 > 백업하기 → 보내기): 사장님이 편한 방법으로
   - **카톡**: 사장님 카톡으로 보내기 → 그 대화방이 곧 보관함 (내가 따로 갖고 있지 않아도 됨)
   - **연락처 주고받기를 꺼리시면**: 그 자리에서 **사장님 폰으로 바로** — 공유 창의 에어드롭(아이폰)·퀵쉐어(안드로이드), 또는 사장님 폰에 앱을 설치해 바로 불러오기. 연락처가 필요 없다
   - **폰으로도 안 받으시면**: "고칠 거 생기면 다시 뽑아 드리게 **2주 확인 때까지만** 백업 하나 갖고 있을게요" 하고 허락받기 → 2주 확인 때 지우기
   - (원하시면) 사장님 폰에 앱 설치: 홈 화면 설치(아이폰은 꼭 — 안 하면 데이터가 지워질 수 있음) → 백업 불러오기
   - 설치하면 사장님 폰 설정 > 사용 통계 보내기 옆 **번호**를 기록표에 적기 (지나가듯 "여기는 쓴 날짜만 저한테 와요" 한마디면 충분)
10. **내 폰 앱 지우기**: 그 자리에서 설정 > **모든 데이터 지우기** → "사진은 방금 다 지웠어요. 백업은 사장님께 드렸어요. 고칠 거 생기면 말씀만 하세요, 그 파일로 바로 다시 뽑아 드릴게요"
    - **수정 요청이 오면**: 카톡 대화방의 백업(또는 사장님이 다시 보내 주신 파일)을 앱에 불러와 고치고 → 다시 뽑아 드리고 → **새 백업을 다시 사장님께** 보내고 → 내 앱은 또 지운다
    - 카톡 파일은 오래 지나면 다시 못 받을 수 있다 → 그땐 "그 파일 한 번만 다시 보내 주세요" (사장님 폰에도 있음)
11. **기록표 채우기**: 세팅 시간, 찾는 시간(전), 설치 여부

- **한 매장을 전달·지우기까지 끝낸 뒤에 다음 매장을 시작**한다 (내 폰 앱엔 데이터가 한 묶음만 들어감)
- **감열 휴대 프린터**(롤지)는 급하게 한 장 다시 뽑을 때·나중에 QR 라벨용. 끝이 톱니로 잘리고 말리며, 햇빛·열·기름에 흐려진다
  - 감열지는 **PVC(말랑한 비닐) 파일에 닿으면 글씨가 지워질 수 있다** → 꼭 **PP** 클리어파일

## 2. 확인 + 조금 더 (12월)

- **2주 뒤**: 들르거나 카톡으로 **딱 한 가지만** — "이거 도움 됐어요, 아니면 그냥 붙어만 있어요?" + 측정(찾기 시험·물어봄 체크표)
- **한 달 뒤**: "계속 사용" = 최근 2주 안에 종이를 보고 찾았거나, 앱으로 검색·수정한 적 있음 + 측정
- 원하는 곳이 있을 때만 2곳 추가 (합쳐 최대 5곳)
- 나온 불편은 2주에 한 번 묶어서 고친다

### 12월 판단 기준 (12월 말, 미리 정해 두고 결과를 보고 바꾸지 않는다)
| 결과 | 다음 |
|---|---|
| 최근에 곤란했던 일을 **스스로 말한** 사람이 2명 이상 + 1곳 이상이 **계속 쓰거나 고쳐 달라고** 한다 | **계속** — 측정한 숫자로 증명하고 3단계로 |
| 다들 "좋네요"만 하고 아무도 안 쓴다 | **줄여서 두기** — 앱은 그대로 두고 시간을 아낀다 |
| 위치 찾기 말고 **다른 아픔**이 반복해서 나온다 | **방향 틀기** — 그 아픔 쪽으로 (예: 사진 매장 매뉴얼) |
| 세 갈래 중 **② 한 번 움직임이나 ③ 자주 움직임** 반응이 매장보다 뜨겁다 | **고객을 바꾼다** — 그 갈래 샘플·첫 화면·영업 말투부터 바꿔 시험 |
| 매장 대화에서 **발주 아픔**(떨어짐·너무 많이 시킴)을 스스로 말한 곳이 위치 아픔보다 많다 + 친구 기록의 **예측이 실제 발주와 대체로 맞는다** (센 물건 절반 이상에서 차이 20% 안) | **무게를 발주로** — 지도는 "세기 입구"로 두고, 식당·카페부터 첫 화면·영업 첫 말을 "발주 실수 줄이기"로. 발주량 예측 화면을 만든다 |

## 3. 결정 (1월)

- 계속 쓰는 곳에 **가격을 넣어** 묻기: "다른 가게에 이렇게 해 드리면 ○만 원 받아도 될까요?" / "월 ○천 원이면 쓰시겠어요?" (자세한 순서는 아래 "돈 이야기")

### 돈 이야기 — 언제·무엇을 묻나 (말보다 행동)
| 시점 | 묻는 것 |
|---|---|
| 첫 대화 (10팀) | 가격은 안 묻는다. **"이거 때문에 지금 쓰는 게 있어요?"** (라벨기·알바 교육 시간 등) → 지금 쓰는 돈이 가격의 기준 |
| 세팅 2주 뒤 | **"이게 없어지면 많이 아쉬우세요, 조금 아쉬우세요, 상관없으세요?"** → "많이 아쉽다"인 곳만 돈 낼 가능성 |
| 한 달 뒤 (계속 쓰는 곳만) | **가격 범위**: "돈 받고 한다면 얼마부터 '비싸다' 싶으세요? 얼마면 적당하다 싶으세요?" |
| 한 달 뒤 → 1월 | **실제 약속**: "다음 달부터 월 ○천 원인데, 먼저 써 주신 분은 평생 반값이에요. 지금 신청해 두실래요?" · "다른 매장에 해 드리면 ○만 원 받으려는데, 소개해 주실 곳 있어요?" |
- 증거의 세기: **미리 낸다** > **소개해 준다** > "좋네요"(증거 아님)

### 돈 받는 방식 후보 (가격은 전부 가설 — 위 질문 답으로 정한다)
| 갈래 | 방식 | 메모 |
|---|---|---|
| ① 매장 | **세팅 대행 1회**(예: 3~10만 원) + 같이 쓰기·백업 **월 구독** + 다시 인쇄·업데이트 **건당** | 처음엔 세팅 대행이 가장 현실적 |
| ② 한 번 움직임 | **이사 1회 이용권**, **이사업체·셀프스토리지 제휴**(업체가 사서 고객에게), 매장 양도 **인수인계 문서 작성 대행**(건당) | 개인보다 **업체가 내는 쪽**이 크다 |
| ③ 자주 움직임 | **저렴한 개인 구독**(예: 월 3~5천 원), 장비팀 **팀 요금**, **QR 박스 라벨 키트** | 반복해서 쓰니 구독이 맞다 |
| 공통 (실물) | **매장 지도 출력·코팅 세트**, **QR 라벨 스티커 키트**를 **스마트스토어**에서 | 실물이라 스마트스토어 정책에 맞고 지금 스토어를 그대로 쓴다 |
- 이 숫자들이 1월 **가격 결정 근거**이자 **초기창업패키지 사업계획서 "수익 모델"** 재료
- **초기창업패키지 사업계획서** 마무리하고 1월 말~2월 중순에 접수 — 11~12월 기록표가 그대로 재료
- 다음에 할 일 **하나만** 고른다
  - 1순위: **세팅 대행 유료** — 개발 없이 바로 시험 가능
  - 후보: 직원과 같이 쓰기, 엑셀로 한 번에 등록 (아래 "아이디어 창고")
- 같이 쓰기처럼 서버가 필요한 기능은 하루 1시간으로 **최소 4~6주** 걸린다고 잡는다

## 4. 첫 수입 시험 (2~3월)

- 세팅 대행을 소개로 받아 본다 (기존 매장 소개 → 다른 사장님)
- 받는 돈이 **배달 시급보다 나은지** 따져 본다 (이동·세팅·인쇄 시간 포함)
- 초기창업패키지 평가 (서류 → 인터뷰 → 발표) 준비
- 사업자는 이미 있음. 돈을 꾸준히 받게 되면 그때 준비: 결제 방법, (서버 저장을 하면) 이용약관·개인정보처리방침

## 5. 여유가 생기면 (이후)

- "베타" 떼기, 요금제 공개
- 직원과 같이 쓰기 → 그 위에 QR 라벨, 바뀐 기록
- 여러 매장 관리, 프랜차이즈 시범, 필요하면 플레이스토어 앱

## 지켜야 할 원칙

1. **배달 수입이 먼저.** 앱은 정해 둔 시간 안에서만 한다.
2. **사장님 할 일은 0.** 부탁하지 않고 해 드린다. 거절하기 쉽게 한다.
3. **새 기능은 멈춤.** 실제로 쓰는 사장님이 말한 것과 데이터 문제만 고친다.
4. **데이터를 잃지 않는 것이 1순위.** 한 번 날아간 매장은 다시 안 쓴다.
5. **기준을 못 넘으면 "줄여서 두기".** 접는 게 아니라 쉬는 모드다. 기준은 결과를 보고 바꾸지 않는다.
6. **"여기까지 왔으니까"는 이유가 아니다.** 계속할 이유는 실제로 쓰는 사람이다.
7. **매장 사진은 내 폰에 오래 두지 않는다.** 백업은 사장님께 드리고(카톡·바로 넘기기), 내 앱은 전달하는 날 바로 지운다. 고칠 땐 사장님 파일로 다시 불러와 고치고 또 지운다. 사장님이 파일을 안 받으시면 허락받고 2주 확인 때까지만 갖는다. 매장과 통계 번호를 이어 적은 기록표는 나만 본다.

| 방법 | 어떻게 | 장점 | 단점 | 언제 |
|---|---|---|---|---|
| ① 전자 가격표(ESL)를 선반 칸마다 | 마트 진열대의 전자 가격표처럼 칸마다 작은 전자종이 ("빨대, 냅킨, 컵홀더") | 칸 바로 앞에서 보이고 원격으로 바뀜 | 기지국·서버가 필요한 기업용 (한국 SoluM이 이 분야 큰 회사). 작은 매장엔 비싸고 무거움 | 프랜차이즈 본사가 낼 때 |
| ② NFC 전자종이 (배터리 없음) | 폰을 대면 NFC로 전기와 그림을 함께 보내 화면을 바꿈 (Waveshare 등) | **서버 없이 됨**, 배터리 관리 없음 | 보통 제조사 앱으로 그림을 넣어야 함, 큰 화면일수록 비쌈 | **해 본다면 이걸 한 장으로 먼저** |
| ③ Wi-Fi 전자종이 게시판 (입구에 한 장) | 큰 전자종이 액자가 정해진 주소의 그림을 주기적으로 받아 띄움 (TRMNL, Inkplate 등) | 앱에서 고치면 입구 "전체 찾아보기"가 저절로 바뀜 | 그림을 올려 둘 **서버가 필요** | 같이 쓰기 서버가 생긴 뒤 |

- 전자종이가 아니어도 되면: 안 쓰는 옛날 폰·태블릿을 입구에 걸어 앱을 띄우는 방법도 있음 (가장 싸지만 충전·관리 필요)
- **판단 기준**: 11~12월 기록표에서 **"위치가 얼마나 자주 바뀌나"** → 자주 바뀌는 매장이 많으면 진짜 답이 될 수 있음
- **작게 시험하려면**: 앱에 **전자종이 크기에 맞는 그림(PNG) 내보내기**만 추가 (인쇄 화면을 이미 그림으로 그려서 어렵지 않음) → 제조사 앱으로 ② 한 장에 넣어 보기
- 지금 하지 않는 이유: 한 장에 수만 원 이상(종이는 몇백 원), ①③은 서버 필요, 하루 1~2시간으로 하드웨어까지 하면 현장 검증이 밀림

### SNS 요소 (10/13 메모) — 공개 피드 말고 "가게 안 팀"과 "사장님끼리"
가게 안 창고를 다루는 앱이라 공개 피드는 사장님들이 꺼린다. 창고 사진을 남에게 보여 주는 기능은 만들지 않는다.

| | 아이디어 | 어떤 모습 | 필요한 것 | 언제 |
|---|---|---|---|---|
| 가게 안 | ① 바뀐 소식 + 확인 👍 | "우유 → 냉장고 2칸으로 옮겼어요 (민수)" → 직원들이 👍로 "봤어요" | 같이 쓰기(서버). "바뀐 기록"과 같은 기능 | 3단계 같이 쓰기와 함께 |
| 가게 안 | **② "어디 있어요?" 질문** | 검색해서 못 찾으면 질문 → 아는 직원이 답 → **답이 지도에 바로 반영** | 같이 쓰기(서버) | 그 뒤 — **가장 잘 맞는 SNS 요소**: 세팅·업데이트 품을 직원들이 나눠서 진다 |
| 가게 안 | ③ 정리 기여 뱃지 | "이번 주 정리왕 🏆" | 같이 쓰기(서버) | 그 뒤 (유치해 보이지 않게 가볍게) |
| 사장님끼리 | ④ 정리 완료 자랑 카드 | "창고 정리 완료! 구역 12 · 물건 85" 카드 이미지 → 사장님 인스타·블로그. 사진은 흐리게 또는 숫자만 | **서버 없음** (인쇄 그림 그리는 코드 재사용) | 현장 반응이 좋으면 |
| 사장님끼리 | ⑤ 업종별 템플릿 나눔 | 구역 구성을 **사진 없이 이름만** 템플릿으로 공유 → 다른 사장님이 가져다 씀 | 서버 | 사용자가 많아진 뒤 |
| 사장님끼리 | ⑥ 사장님 소개 혜택 | "소개하면 둘 다 한 달 무료" | **개발 0** — 처음엔 말로 하고 손으로 기록 | **지금 해도 됨** |
| 사장님끼리 | ⑦ 신입 환영 링크 | 새 알바에게 카톡으로 "우리 가게 창고 투어" 링크 → 첫 출근 전에 미리 보기 | 같이 쓰기(서버) | 3단계 같이 쓰기와 함께 |

- 하지 않는다: **공개 피드·동네 사장님 커뮤니티** (신고·광고·다툼 관리에 시간이 너무 든다), **창고 사진을 남에게 보여 주는 기능**

### 포스기 연동 구상 (10/14 메모)
센 기록만으로도 "얼마나 썼나"는 나온다. 포스기는 **"왜 썼나"(무엇이 팔려서)**와 **요일·행사 패턴**을 더해 준다.

**흐름**: 포스기 판매 기록 → (레시피) → 쓴 재료 → 지금 수량에서 빼기 → 발주량 예측
- 소매(편의점·약국·문구): 판 물건 = 재고 물건 (1:1). 레시피 필요 없음
- 카페: **아메리카노 1잔 = 컵 1 · 뚜껑 1 · 홀더 1 · 원두 20g** — 앱에 적힌 소모품과 바로 맞음 (가장 잘 맞는 업종)
- 식당: 김치찌개 1 = 김치 200g · 두부 ½모 — 레시피 적기가 일이라 처음엔 **주재료 몇 개만**

**단계** (위로 갈수록 쉽다)
| 단계 | 어떻게 | 필요한 것 | 판단 |
|---|---|---|---|
| ① 판매 엑셀 올리기 | 사장님이 포스기 관리 사이트에서 **"상품별 판매" 엑셀(CSV)**을 내려받아 앱에 올림 → 메뉴별 판매 수 | 서버 없음. 포스기마다 파일 모양이 달라 맞춰 읽기 (한 종류에 몇 시간) | **해 본다면 이것부터** — 쓰는 포스기를 먼저 물어보고 한 종류만 |
| ② 메뉴 ↔ 재료 연결 | 메뉴마다 "무엇을 몇 개 쓰나" 한 번 적기. 처음 올린 파일의 메뉴 이름으로 목록을 만들어 줌 | 서버 없음 | ①과 함께. 업종 템플릿(카페 기본 레시피)으로 품을 줄임 |
| ③ 이론 재고와 비교 | 지난번 센 수 − 판매로 쓴 양 = 있어야 할 수 ↔ 실제로 센 수. 차이 = **버림·실수·도난(로스)** | 서버 없음 | 사장님이 돈으로 느끼는 숫자 — 유료 기능 후보 |
| ④ 자동 연동 (API) | 포스기 회사와 연결해 판매가 저절로 들어옴 | 서버 + 포스기 회사 제휴·심사. 회사마다 다름 | 사용자가 많아진 뒤. 공개 API가 있는 회사가 있는지 **그때 다시 확인** |

- 지금 하지 않는 이유: 센 기록 예측이 맞는지부터 확인. 포스기 종류가 많아 **실제 쓰는 곳**이 정해져야 어느 파일부터 읽을지 정할 수 있다
- 확인할 것: 10팀에게 "포스기 뭐 쓰세요? 관리 사이트에서 판매 엑셀 받아 본 적 있어요?" — 같은 포스기가 몰리면 그 하나만 ①
- **국내 포스 API 조사 (10/14)** — ④는 지금 사실상 **토스플레이스 하나**만 공개 문서가 있다
  - 토스플레이스: 개발자센터에서 앱 등록 → Access Key/Secret, 주문 조회 API·웹훅, 테스트 가맹점으로 개발 가능 (docs.tossplace.com). 단 **키를 숨길 서버 필요**, 실제 매장 오픈엔 토스 프론트 단말기 필수, 운영 심사 절차는 문서에서 못 찾음 → developer-support@tossplace.com
  - 페이히어: 엔터프라이즈용 Open API 안내만 (도입 문의 필요)
  - OKPOS: 공개 API 없음. 본사 단위 매출 연동은 partnership@okpos.co.kr 제휴 문의
  - 배민포스: 공식 외부 연동 문서 못 찾음
  - 그래서 순서: ① 판매 엑셀 → (토스 쓰는 매장이 몰리면) 토스 Open API + 작은 서버
- **엑셀 받아 오는 귀찮음 줄이기 (10/14)** — 먼저: 센 기록만으로 예측이 되면 판매 기록은 로스·요일 패턴용일 뿐
  - 추천: **마감 정산서(또는 포스 화면) 사진 한 장** → AI가 메뉴별 판매 수를 읽고 확인 목록으로 보여 준 뒤 넣기. 포스 종류 상관없음, AI 통로는 이미 있음. 정산서에 메뉴별 수가 찍히는지 먼저 확인
  - 같이: 안드로이드는 포스 관리 앱에서 [공유] → 창고여지도 (아이폰 웹앱은 공유 받기 미지원) · 매일이 아니라 **[재고 세기] 시작할 때만** "지난번 이후 판매 올리기" · 개발 없이: 마감 알바 할 일에 "정산서 찍기"
